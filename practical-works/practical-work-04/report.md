### 1. Описание проведения мозгового штурма
*   **Метод:** Асинхронный мозговой штурм с использованием мессенджера (Telegram).
*   **Правила:** На первом этапе действовал строгий запрет на критику и оценку идей. Каждый участник предложил по 3 и более варианта функционала для будущего продукта (бота-планировщика). На втором этапе было проведено коллективное голосование за наиболее полезные и реализуемые в рамках учебного проекта идеи.
*   **Длительность:** Обсуждение и генерация идей заняли около 1 часа, голосование проводилось после фиксации всех предложений.

### 2. Полный список сгенерированных идей

Основные направления генерации включали:
*   Автоматическое распределение задач по важности и срочности.
*   Напоминания о дедлайнах и геолокационные триггеры.
*   Интеграция с расписанием РГРТУ через API и электронной почтой.

*   Групповой режим для команд.
*   Мультиплатформенность.
*   Использование нейросетей для распознавания речи и адаптации под пользователя.

### 3. Результат группировки и отбора (с обоснованием)
По итогам голосования команда отобрала **5 наиболее значимых идей**, которые сформировали ядро концепции продукта. Отобранные идеи были разделены на два ключевых блока:

**Блок 1: Интеллектуальное планирование и адаптация (Smart Scheduling)**
*   *Идея 1 (Виталя):* Бот анализирует и переносит невыполненные задачи, уточняя причину невыполнения, и корректирует приоритеты.
*   *Идея 2 (Виталя):* Бот собирает данные о времени выполнения задач (пики/спады активности) и распределяет сложные задачи на пики, а простые — на спад.

**Блок 2: Нейросетевой ассистент и удобство ввода (AI Integration)**
*   *Идея 3 (Xerji):* Голосовой ввод задач с распознаванием через VAD и обработкой текста нейросетью.
*   *Идея 4 (Xerji):* Работа сервиса через API ключ нейросети (запоминание контекста пользователя в краткой форме для адаптации).
*   *Идея 5 (DanilSfq):* Автоматическое создание шаблонов на основе повторяющихся последовательностей действий.

*Обоснование отбора:* Данные идеи были выбраны, так как они решают главную проблему целевой аудитории (студентов и молодых специалистов) — нехватку времени и прокрастинацию. Использование ИИ (голосовой ввод, анализ контекста, автоперенос задач) делает продукт уникальным и значительно снижает трудозатраты пользователя на ведение ежедневника.

### 4. Итоговый перечень функциональных требований
На основе отобранных идей были сформулированы следующие функциональные требования к системе:

*   **FR-1:** Система должна предоставлять возможность переноса невыполненных задач с обязательным запросом причины невыполнения.
*   **FR-2:** Система должна автоматически корректировать приоритет перенесенных задач на основе указанной пользователем причины.
*   **FR-3:** Система должна анализировать статистику выполнения задач пользователем и определять его индивидуальные «пики» и «спады» активности в течение дня.
*   **FR-4:** Система должна автоматически распределять задачи разной сложности по времени суток, предлагая сложные задачи на периоды пиковой активности пользователя.
*   **FR-5:** Система должна поддерживать функцию голосового ввода новых задач с использованием технологии распознавания речи (VAD) и последующей обработки естественного языка нейросетью.
*   **FR-6:** Система должна использовать API нейросети для формирования и хранения краткосрочного контекста пользователя (адаптация под стиль общения и привычки).
*   **FR-7:** Система должна автоматически выявлять часто повторяющиеся последовательности задач и предлагать пользователю сохранить их в качестве готового шаблона.

### 5. Вывод о соотношении требований с потребностями аудитории
Разработанные функциональные требования напрямую отвечают потребностям целевой аудитории. Основной фокус сделан на снижении когнитивной нагрузки (FR-5, FR-7 позволяют быстро добавлять задачи) и гибком планировании (FR-1, FR-2, FR-3, FR-4 решают проблему выгорания и неэффективного распределения времени). Интеграция ИИ (FR-6) позволяет создать персонализированного помощника, который подстраивается под ритм жизни пользователя, что делает процесс планирования максимально комфортным и результативным.

### 6. Ответы на контрольные вопросы
1.  **Что такое мозговой штурм и каковы его основные правила?**
    Это метод коллективной генерации идей. Правила: запрет критики на этапе генерации, поощрение нестандартных идей, большое количество предложений, возможность комбинировать идеи.
2.  **Почему на этапе генерации идей критика запрещена?**
    Критика подавляет креативность и страх показаться глупым. Запрет критики позволяет участникам свободно высказывать любые, даже самые фантастические идеи, которые позже могут трансформироваться в отличное решение.
3.  **Что такое функциональное требование?**
    Это описание того, что система должна делать (какие функции выполнять), как она должна реагировать на входные данные и какие задачи решать для пользователя.
4.  **Как связаны целевая аудитория и функциональные требования?**
    Требования формируются исходя из болей и потребностей ЦА. Изучив аудиторию (СР №3), мы знаем, какие функции будут для них полезны, а какие — бесполезны.
5.  **Зачем фиксировать все идеи, даже «неудачные»?**
    «Неудачная» идея может стать основой для отличного решения при небольшой доработке. Кроме того, фиксация всех идей показывает широту охвата проблемы и помогает не упустить важные детали.
